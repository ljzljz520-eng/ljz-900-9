# 连锁药店巡检整改平台

督导巡检上报 → 店员扫码整改 → 老板汇总考核 的闭环管理工具。

## 启动

```bash
npm install
npm start          # http://localhost:3000
```

## 角色与页面

| 角色 | 页面 | 功能 |
|------|------|------|
| 督导 | `/supervisor.html` | 按门店上传**药品陈列 / 冷藏柜 / 处方区**问题照片，设定扣分与描述 |
| 店员 | `/rectify.html?code=门店码` | 扫描本店二维码进入，查看待整改项并上传整改照片 |
| 老板 | `/dashboard.html` | 问题与整改**成对图片**对比、扣分项、各店及整体**完成率** |
| 管理 | `/index.html` `/qr.html` | 门店管理、打印门店整改二维码 |

## 关键设计

- **编号全局连续且各页一致**：展示编号 `ZG-001…` 不固化存储，基于**全部问题**按上报时间统一排序动态生成；删除任意记录后自动重排，同一问题在全店列表、单店筛选、扫码页、汇总页编号始终一致。
- **图片即删即清**：删除问题/门店时同步删除服务器上的问题图与整改图；重新上传整改图自动覆盖删除旧图；上报参数校验失败时清理已落盘文件，不留孤儿文件。
- **二维码整改**：每店一个专属二维码（`/api/stores/:id/qrcode`），链接带门店码，店员无需登录；二维码页支持直接打印张贴。
- **老板汇总**：整体/单店完成率、扣分项与整改找回分、按「药品陈列/冷藏柜/处方区」分类完成率，问题图与整改图成对对比。
- **存储**：`data/db.json`（原子写入）+ `uploads/` 图片目录（启动自动创建），零原生依赖。

## API 摘要

- `POST /api/issues` 督导上报（multipart: storeId, category, deductPoints, description, image）
- `POST /api/issues/:id/rectify` 店员上传整改图
- `DELETE /api/issues/:id` 删除（编号自动重排）
- `GET /api/summary` 老板汇总（完成率、扣分）
- `GET /api/stores/:id/qrcode` 门店整改二维码 PNG
